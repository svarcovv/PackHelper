# Как обновляю приложение и ресурспак

Код менять не нужно. Сборщик сам упакует новый ZIP в EXE и рассчитает контрольные суммы. Так пак остаётся доступен игроку без интернета.

1. Беру точный ZIP, который будет использовать сервер.
2. Открываю папку проекта и запускаю `release.cmd`. Если исходников нет под рукой, скачиваю их с GitHub и распаковываю.
3. Выбираю ZIP, указываю новую версию приложения и версию ресурспака, нажимаю **Собрать выпуск**.
4. На GitHub создаю новый выпуск с тегом **v + версия приложения**. Например, `v1.5.2`.
5. Прикладываю только EXE и `update.json` из папки `dist`, затем публикую выпуск. `pack-release.json` и `SHA256SUMS.txt` остаются локальными файлами сборки.

После публикации PackHelper проверит версию при следующем запуске и покажет результат на странице «Обновления». Проверку можно запустить и вручную. Номер приложения увеличиваю при каждом выпуске, даже когда меняется только пак.

На сервере обновляю ссылку на ZIP и `pack.sha1`. UUID `pack.id` сохраняю. Значения должны совпадать с `pack-release.json`; ZIP после сборки не перепаковываю.

## Сборка командой

Windows 10 или 11, .NET Framework 4.8:

```powershell
.\test.ps1
.\build.ps1 -PackPath '.\LavaResurs.zip' -PackVersion '1.11.7' -AppVersion '1.5.2'
.\test-ui.ps1 -ExecutablePath '.\dist\PackHelper-1.5.2.exe'
```

Версия тега важна: `update.json` содержит прямой адрес EXE из этого выпуска. Проверки установки и обновления запускаются в GitHub Actions.

## Передать проект другому разработчику

Передаю папку с исходниками и точным ZIP ресурспака. В полном архиве проекта ZIP лежит в `resourcepack`, сборщик подставит его сам. Для изменений интерфейса есть `src/Window.xaml` и `src/Theme.xaml`, логика находится рядом в `src`, проверки в `tests`.

Для официального выпуска нужен закрытый ключ `PackHelper.ReleaseSigning.v1` в хранилище текущего пользователя Windows на компьютере владельца. В репозитории и приложении хранится только открытый ключ. Сборщик подписывает `update.json`; без правильного закрытого ключа выпуск не пройдёт проверку у игроков.

На другом компьютере для проверки изменений можно собрать EXE с параметром `-UnsignedDevelopment`. Такой файл подходит для локальных тестов, но его нельзя публиковать как официальное автообновление.
